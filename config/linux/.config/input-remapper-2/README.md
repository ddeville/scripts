# Framework input mappings

The keyboard and touchpad presets work together. Names below refer to the
physical keys; applications see the remapped modifiers.

| Physical input | Output |
| --- | --- |
| Caps Lock or left Alt | Ctrl |
| Right Alt or left Ctrl | Super |
| Windows | Alt, plus the touchpad right-click modifier |
| Touchpad click | Left click |
| Windows + touchpad click | Right click |
| Left Ctrl + touchpad left button | Super + left click (Hyprland move) |
| Left Ctrl + Windows + touchpad click | Super + right click (Hyprland resize) |

With left Ctrl held, a hardware right-button event also produces Super + right
click. The touchpad preset maps unmodified left- and right-button events to
left click. Hyprland disables tap-to-click; taps would be generated by libinput
after input-remapper and would bypass these button macros.

The Windows-key and touchpad macros must both target `keyboard + mouse`.
Resizing releases Alt for the remainder of that Windows-key hold. Release and
press Windows again to use it as Alt afterward; repeated resizing still works
while Windows is held. Only the keyboard macro presses Alt. The touchpad must
not restore it after a resize, because its flag check and the keyboard's release
run in separate processes and can race. Both macros use the same virtual device
so that Alt's press and release affect the same per-device key state.

Use `hold(KEY)` for these single-key holds. In input-remapper 2.2.1,
`hold_keys(KEY)` yields after both press and release, even with a zero delay.
Those extra yields can swallow rapid clicks or delay clearing modifier flags.

The presets load at login through XDG autostart. To reload them, release all
modifiers and mouse buttons, then run:

```sh
systemctl --user restart 'app-input\x2dremapper\x2dautoload@autostart.service'
```
